MCP (Model Context Protocol) lets Dline use external tools and data sources through MCP servers.

## What MCP gives you

- Connect Dline to external APIs and services
- Add custom tools beyond built-in Dline tools
- Use either local servers or remote hosted servers

## Quick start

1. Open **MCP Servers** in the Dline panel.
2. Add a server from the Marketplace or open the configuration editor.
3. Configure the local command or remote URL and required credentials.
4. Confirm the server connects and its tools appear before using them in a task.

## Add servers

### Option 1: Marketplace

1. In the Dline panel, click the **MCP Servers** icon.
2. Open the **Marketplace** tab.
3. Review the server source and requested setup before installing it.

### Option 2: Global settings

1. In the Dline panel, click the **MCP Servers** icon.
2. Open the **Configure** tab.
3. Click **Configure MCP Servers**.
4. Add or update entries under `mcpServers` in the JSON file Dline opens.

The file is stored at `settings/mcp_settings.json` under the Dline documents root, normally `~/Documents/dline/settings/mcp_settings.json`. If `DLINE_DOCS_DIR` is set, that variable already identifies the documents root.

For a hosted endpoint, you can instead use the **Remote Servers** tab, enter a unique name and full URL, choose **Streamable HTTP** or legacy SSE, and select **Add Server**.

### Option 3: Workspace descriptors

Projects can publish reviewed MCP descriptors under `.agents/mcp/` using `.yaml`, `.yml`, or `.json` files. Workspace descriptors are scoped to that workspace and never grant auto-approval by themselves.

Sensitive fields must reference environment variables rather than embedding credentials, for example `${env:MCP_TOKEN}`. You can use `${workspaceFolder}` in path values that should resolve from the project root.

## Configuration examples

### Local server (STDIO)

```json
{
  "mcpServers": {
    "local-server": {
      "command": "node",
      "args": ["/path/to/server.js"],
      "env": {
        "API_KEY": "your_api_key"
      },
      "disabled": false,
      "autoApprove": []
    }
  }
}
```

### Remote server (HTTP/SSE)

```json
{
  "mcpServers": {
    "remote-server": {
      "url": "https://example.com/mcp",
      "headers": {
        "Authorization": "Bearer your-token"
      },
      "disabled": false,
      "autoApprove": []
    }
  }
}
```

## Transport types

- **STDIO**: local process, lower latency, simpler local setup
- **Remote HTTP/SSE**: hosted endpoint, centralized deployment, supports multi-client usage

Use STDIO for local tools and remote transport for shared hosted services.

## Managing servers

In MCP settings you can:

- Enable/disable servers
- Restart unresponsive servers
- Set request timeouts
- Remove servers

## Security basics

- Only install servers you trust.
- Keep credentials out of repository files and use environment references in workspace descriptors.
- Treat `autoApprove` as a task permission, not a capability granted by an MCP descriptor.
- Review tool calls and server output before approving side effects.

## Troubleshooting

| Issue | Fix |
|---|---|
| Server won't connect | Verify command/URL, server process status, and port |
| Missing tools | Confirm server started successfully and tools are exposed |
| Auth errors | Re-check API keys/tokens and required headers |
| Timeout errors | Increase MCP timeout and test server response directly |
