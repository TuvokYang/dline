Dline uses separate roots for durable state, runtime resources, user documents, and project capabilities. These locations have different owners and should not be merged into one configuration directory.

## Storage Locations

### State and data root

The default state root is `~/.dline/data/`. It contains canonical settings, workspace state, profile metadata, and secrets:

```text
~/.dline/data/
├── globalState.json
├── secrets.json
├── settings/
│   ├── settings.json
│   └── api_profiles.json
├── secrets/
│   ├── api_keys.json
│   └── provider_secrets.json
└── workspaces/
    └── <workspace-hash>/
        ├── workspaceState.json
        └── settings.json
```

Do not edit these files while Dline is running. Settings and profiles use repository-owned update paths so multiple VS Code windows do not overwrite one another with stale snapshots.

### Resource home

The default resource home is `~/.dline/`. It owns resources such as provider metadata, caches, Puppeteer data, and `endpoints.json`:

```text
~/.dline/
├── endpoints.json
├── providers/
├── cache/
└── puppeteer/
```

### Documents root

User-facing task data and global capabilities live under the operating system's Documents directory, normally `~/Documents/dline/`:

```text
~/Documents/dline/
├── tasks/
├── rules/
├── workflows/
├── skills/
├── subagents/
├── mcp/
├── hooks/
├── settings/
│   └── mcp_settings.json
└── checkpoints/
```

`DLINE_DOCS_DIR` is already the final Dline documents root. When it is set, Dline does not append another `dline` directory.

## Project Capabilities

Repository-scoped capabilities use explicit project paths:

```text
your-project/
├── .agents/
│   ├── rules/
│   ├── workflows/
│   ├── skills/
│   ├── subagents/
│   └── mcp/
└── .agentignore
```

Commit the `.agents/` resources and `.agentignore` policy that are intended for collaborators. Keep credentials out of the repository. Workspace MCP descriptors reject inline secrets in sensitive fields and require environment-variable references.

## Environment Variables

| Variable | Description | Default |
|----------|-------------|---------|
| `DLINE_DIR` | Parent directory for the state/data root; Dline appends `data/` | `~/.dline` |
| `DLINE_HOME_DIR` | Resource home for providers, cache, Puppeteer data, and endpoints | `~/.dline` |
| `DLINE_DOCS_DIR` | Complete documents root for tasks and global capabilities | system Documents directory plus `dline` |
| `DLINE_COMMAND_PERMISSIONS` | JSON policy restricting shell commands | unset |

Set path overrides before launching VS Code so the extension host inherits them. For an isolated environment, set all three path variables; overriding only one root does not isolate the others.

### DLINE_COMMAND_PERMISSIONS

Restrict which shell commands Dline can execute:

```bash
export DLINE_COMMAND_PERMISSIONS='{"allow": ["npm *", "git *"], "deny": ["rm -rf *"]}'
```

Format:

```json
{
  "allow": ["pattern1", "pattern2"],
  "deny": ["pattern3"],
  "allowRedirects": true
}
```

Rules:

- `deny` overrides `allow`
- If `allow` is set, commands not matching `allow` are denied
- `allowRedirects` controls shell redirects (`>`, `>>`, `<`), default `false`

## Security Notes

<Warning>
Never commit API keys, provider credentials, or MCP tokens. Review rules, skills, workflows, subagent profiles, and MCP descriptors before enabling resources from another repository.
</Warning>

Dline's current public extension surface does not provide a stable third-party plugin or lifecycle-hook installation API. The linked Hooks and Plugins pages describe the planned boundaries rather than an installable contract.
