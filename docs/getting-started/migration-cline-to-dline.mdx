title: "Migrating from Cline to Dline"
description: "Automatically transfer your data, settings, tasks, and configuration from Cline to Dline on first launch"
---

## Overview

When you install Dline after previously using Cline, all your data is automatically migrated on the first launch. The migration copies your settings, API keys, task history, and configuration files from the legacy Cline paths to the new Dline paths.

**The migration is non-destructive** — original Cline files are never deleted. You can safely roll back to Cline at any time.

## What Gets Migrated

The migration transfers data across **5 paths**, preserving your complete working environment:

### 1. Core Data Directory

```
~/.cline/data/  →  ~/.dline/data/
```

Copies legacy global state, secrets, and workspace state into Dline's current state/data root for the VS Code extension.

### 2. Custom Endpoints

```
~/.cline/endpoints.json  →  ~/.dline/endpoints.json
```

Transfers any custom API endpoint configurations you've set up.

### 3. Task History

```
VS Code Global Storage/state/taskHistory.json  →  Documents/dline/tasks/
```

Your complete conversation history, task metadata, and past sessions.

### 4. Individual Task Directories

```
VS Code Global Storage/tasks/*/  →  Documents/dline/tasks/*/
```

All individual task conversation histories, UI messages, and metadata. Migrates all completed tasks.

### 5. Documents Directory

```
~/Documents/Cline/  →  ~/Documents/dline/
```

Copies the legacy Documents/Cline folder into the current Dline documents root so supported tasks and capability files remain available for later normalization.

## How It Works

### Automatic Migration

The migration runs **once**, automatically, when Dline starts for the first time after an install or update. You'll see a VS Code progress notification:

> "Migrating your Cline data to Dline..."

Each migration step is checked independently — only missing files are copied. If you've already run Dline before (i.e., `~/.dline/data/` already exists), the migration is skipped.

### Progress Reporting

The migration shows a progress indicator during startup. Each of the 5 steps reports success or failure. Failed steps are logged as warnings but never block the extension from starting.

### Skipping Migration

Migration is **automatically skipped** when Dline detects that you're running in a development or isolated environment:

- `DLINE_HOME_DIR` environment variable is set
- `DLINE_DOCS_DIR` environment variable is set

This prevents accidental data copying during development and testing (e.g., fresh install mode with `dist/tmp` paths).

If you want to skip migration in a production environment, set either environment variable before launching VS Code.

## Environment Variables

Dline supports the following environment variables for controlling paths and migration behavior:

| Variable | Purpose | Default |
|---|---|---|
| `DLINE_HOME_DIR` | Override the home config directory | `~/.dline` |
| `DLINE_DOCS_DIR` | Override the complete Dline documents root | `~/Documents/dline` |
| `DLINE_DIR` | Override the shared storage directory (used by `storage-context`) | `~/.dline` |

Setting `DLINE_HOME_DIR` or `DLINE_DOCS_DIR` skips automatic migration. `DLINE_DIR` changes the state/data root but is not, by itself, a migration skip flag.

## Dline Path Structure

After migration, your Dline data lives in:

```
~/.dline/                           # Config & state (shared storage)
  ├── data/
  │   ├── globalState.json          # Settings, preferences, provider configs
  │   ├── secrets.json              # API keys (restricted permissions)
  │   └── workspaces/<hash>/        # Per-workspace state

~/Documents/dline/                  # Tasks and global capabilities
  ├── tasks/                        # Task database and per-task files
  │   ├── taskHistory.db
  │   └── <task-id>/
  ├── rules/                        # Global rules
  ├── skills/                       # Global skills
  ├── workflows/                    # Global workflows
  ├── subagents/                    # Global subagent profiles
  ├── mcp/                          # MCP server files
  ├── hooks/                        # Hook files
  ├── settings/mcp_settings.json    # MCP connection settings
  └── checkpoints/                  # Checkpoint repositories
```

## Verifying Migration

After Dline launches, verify the migration was successful:

1. Check that your **API keys** are preserved — open Settings and verify your provider configuration
2. Open the **History** tab and confirm your past conversations are visible
3. Verify any **custom rules** or **MCP servers** are present

If anything is missing, you can manually copy files from the Cline paths to the Dline paths listed above.

## Manual Migration

If the automatic migration doesn't run (e.g., you've used Dline before and new data was added to Cline later), you can manually copy files:

```bash
# Core data
cp -r ~/.cline/data/ ~/.dline/data/

# Endpoints
cp ~/.cline/endpoints.json ~/.dline/endpoints.json

# Documents
cp -r ~/Documents/Cline/ ~/Documents/dline/
```

<Note>
The original Cline files are never modified or deleted. You can safely keep both Cline and Dline installed side by side.
</Note>

## Troubleshooting

**Migration skipped unexpectedly?**
Check if `DLINE_HOME_DIR` or `DLINE_DOCS_DIR` is set in your environment. These variables cause migration to be skipped.

**Missing task history?**
Task history migration reads from VSCode's global storage, which is platform-specific. On Windows, this is typically under `%APPDATA%/Code/User/globalStorage/`. If you're using a different editor (Cursor, Windsurf, etc.), the path will differ.

**Missing custom rules or agents?**
The Documents/Cline directory migration only runs if `~/Documents/dline/` does not exist yet. If it already exists from a previous Dline installation, manually copy only the missing files you still need from `~/Documents/Cline/`.

**Rolling back to Cline?**
Simply uninstall Dline and continue using Cline. All original Cline files remain untouched — nothing needs to be restored.
