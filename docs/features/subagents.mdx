Subagents 让 Dline 启动相互隔离的研究代理。每个 Subagent 都有独立的提示词、上下文窗口、工具白名单和可见 Skill 集合，并将结果返回主代理，从而避免把全部调查材料塞入主上下文。

<Tip>
  Subagents is an experimental feature. Behavior may change in future releases.
</Tip>

## How It Works

Dline 可以使用 `use_subagent` 启动一个 default 或具名 Subagent，也可以使用 `use_subagents` 启动一到五个并行的 default 子任务。不同具名代理需要分别调用 `use_subagent`；批量入口不支持为每一项指定不同的代理或 Profile。

每个 Subagent 使用独立的任务提示词、上下文窗口与输出预算，并把结论返回主任务。委派时应明确问题、范围、已有证据和预期结果，不能假定子代理已经看到主任务的完整对话。

随产品提供的 default 是只读调研配置，可以读取文件、搜索代码、列出目录、查看代码定义和按需加载 Skill，不开放命令执行、文件写入、浏览器、Web 或 MCP。具名代理可以在 YAML 中显式配置其他工具，权限边界见下文。

Subagent costs (tokens and API spend) are tracked separately per subagent and rolled into the task's total cost. You can see per-subagent stats (tool calls, tokens, cost) in the chat UI as they run.

## Final Result Output Budget

具名 Subagent 的 YAML frontmatter 可以通过 `maxOutputTokens` 控制最终返回主任务的 `attempt_completion.result` 大小。该字段的单位始终是 token，而不是字符：

```yaml
---
name: reviewer
description: Research and exploration subagent
maxOutputTokens: 0.05
---
Investigate the requested code paths and return concise, evidence-backed findings.
```

- 不配置时，默认使用启动该 Subagent 时主任务剩余上下文窗口的 5%。
- `0 < maxOutputTokens < 1` 表示比例，例如 `0.05` 表示剩余窗口的 5%。
- 正整数表示固定 token 数，例如 `10240`；实际生效值不会超过主任务当时的剩余窗口。
- 生效预算会注入 Subagent 的任务提示词，Subagent 必须据此组织最终报告。
- 该限制只约束最终 `attempt_completion.result`，不会把每一轮工具调用或 Provider 请求截断；返回前会再次执行同一 token 预算的硬限制。

如果项目使用 UTF-8 文本估算 token，运行时采用保守的字节估算，因此最终结果可能略短于配置值，这是为了避免把超长结果重新注入主任务上下文。

## Enabling Subagents

Subagents 默认启用。Dline 会根据任务选择是否委派，你也可以明确要求使用某个具名代理。可在能力设置中管理子代理配置与工具开关。

This setting applies to tasks in the Dline VS Code extension.

## Using Subagents

启用后，Dline 可以在需要跨模块调查时使用 Subagents。你也可以明确指定代理、研究问题和只读边界。

Example prompts:

- "Use subagents to explore how authentication works and where the database models are defined"
- "Spin up subagents to investigate the API routes, the test setup, and the deployment config"
- "I'm new to this codebase. Use subagents to map out the main entry points, the routing layer, and the data access patterns"

每个子代理任务应只回答一个明确问题。问题较小时只运行一个子代理即可；不同问题互不依赖时再并行，最后由主任务核对证据并整合结论。

## 按职责选择 Profile

主任务可以使用适合实现代码的模型，同时让代码检索、架构审查和联网调研代理分别使用其他模型或服务商。这里有两个不同的配置对象：

| 配置 | 决定什么 |
|---|---|
| API Profile | 服务商、会话模型、凭据、Thinking 配置、Web Search 路由与图像源 |
| 具名 Subagent YAML | 代理职责、引用哪个 API Profile、允许哪些工具、可见哪些 Skill，以及最终输出预算 |

先在 **API Configuration** 中创建并启用需要的 API Profile，勾选 **Subagents** 用途，再到子代理设置中选择它。也可以直接在 `.agents/subagents/<name>.yaml` 中填写 `profile`。项目与全局有同名代理时，项目配置优先。

### 代码检索与深度审查使用不同模型

下面的例子假定已创建名为 `Fast Research` 的 API Profile，并启用 Subagents 用途。将其保存为 `.agents/subagents/code-researcher.yaml`：

```yaml
---
name: code-researcher
description: Read-only codebase research
profile: "Fast Research"
tools:
  - read_file
  - list_files
  - search_files
  - list_code_definition_names
skills: []
maxOutputTokens: 0.05
---
Trace the requested code paths without changing files. Return findings with file paths, evidence, and open questions.
```

再创建一个 `architecture-reviewer`，把它的 `profile` 改为已配置的深度推理 Profile，并在正文中写明审查目标。随后可以这样委派：

```text
让 code-researcher 查清登录请求的调用链，再让 architecture-reviewer 检查这些路径的模块边界。
都只读调查，不修改文件；分别给出证据、风险和未确认的问题。
```

有效的显式 `profile` 绑定使用该 Profile 的模型与 Thinking 配置，不套用父任务的任务级 Thinking 覆盖。省略或清空 `profile` 时，继承父任务的 **Act Profile**，即使父任务当前处于 Plan 模式。Profile 在本次子代理启动时解析，不是由模型在每轮调用中任意选择凭据；配置模型请使用 `profile`，旧的 `modelId` 字段已不再生效。

<Note>
  普通子代理的 Profile 引用不存在、名称有歧义、已禁用或未勾选 Subagents 用途时，当前实现会回落到父任务的 Act Profile。需要固定模型或服务商时，请先核对 Profile 配置，不要把错误名称当作阻止调用的保护措施。开放 `generate_image` 的代理采用更严格的规则：必须显式绑定有效 Profile，否则启动失败，不借用父任务的图像凭据。
</Note>

### 联网、MCP 与图像能力按需组合

`profile` 选择会话配置，`tools` 决定向代理开放哪些工具。换成某个模型并不会自动开放 Web、MCP 或图像生成。

| 用途 | 工具与配置 |
|---|---|
| 联网调研 | 开放 `web_search` / `web_fetch`，并启用 Web Tools；托管 Web Search 的路由取决于所绑定的 API Profile 与模型能力 |
| 专业分析 | 开放 `load_skill`，通过 `skills` 声明可见技能；正文在调用时才加载 |
| 查询 MCP 服务 | 开放 `load_mcp` / `use_mcp_tool`，并在当前任务启用对应服务器；加载说明不等于执行工具 |
| 生成或编辑图片 | 开放 `generate_image`，显式绑定 API Profile，并在该 Profile 内配置图像源与模型 |

例如，先准备一个名为 `Research With Images` 的 API Profile，启用 Subagents 用途并配置图像源，再保存 `.agents/subagents/visual-researcher.yaml`：

```yaml
---
name: visual-researcher
description: Web research and requested image generation
profile: "Research With Images"
tools:
  - read_file
  - web_search
  - web_fetch
  - generate_image
skills: []
maxOutputTokens: 4096
---
Research the requested topic and cite sources. Generate or edit images only when explicitly requested. Return findings and image artifact references.
```

在这个 API Profile 的图像设置中选择可用的图像源和图像模型，具体选项受服务商与模型能力限制。选择 Independent 时可以关联独立 Image Profile，从而把会话模型与图像模型分开；YAML 不需要、也不支持额外的 `imageProfile` 字段。Web Fetch 是单独开放的抓取工具，没有独立的 Web Fetch Profile。

工具白名单不代替 Web、MCP、图像或文件操作的权限检查。只做代码研究时，保留前一个只读示例即可，不必为所有代理开放全部工具。完整工具含义见[工具参考](/tools-reference/all-dline-tools)，技能配置见[Skills](/customization/skills)。

## Auto-Approve Behavior

Subagent 的启动遵循 **Read project files** 自动审批设置。开启时可以自动启动；关闭时先展示委派内容并请求批准。详见[自动审批](/features/auto-approve)。

启动批准不代表所有工具都无条件执行。具名代理的文件修改、Web、MCP 和图像生成仍使用各自的权限与审批策略。

<Warning>
  给具名代理开放 `execute_command` 时要格外谨慎：当前实现对已获准启动的子代理，在工作区内执行命令不会逐条再次弹出命令审批。命令仍受命令权限配置、目录执行权限和外部工作目录审批约束。只读调研不要开放该工具；内置 default 不提供命令执行。
</Warning>

## What Subagents Can Do

下面是随产品提供的 default 只读配置。具名代理可以通过 `tools` 显式配置不同的工具集合，不应把所有 Subagent 都视为只读沙箱。

| Tool | Purpose |
|------|---------|
| `read_file` | Read file contents |
| `list_files` | List directory contents |
| `search_files` | Regex search across files |
| `list_code_definition_names` | List top-level classes, functions, and methods |
| `load_skill` | 按精确名称加载一次 Skill 完整指令，并直接遵循返回内容 |

`attempt_completion` 会自动加入工具集合，用于返回最终结果，无需在 YAML 中重复声明。省略 `tools` 或写成空数组会使用默认工具集，不代表禁用全部工具；若只需要直接返回结果，可以显式写 `tools: [attempt_completion]`。

`skills` 只控制提示词中的可见 Skill 清单，不预加载正文，也不替代底层能力开关。不存在或已禁用的 Skill 会从清单中移除并记录 warning；实际加载仍受当前任务启用范围约束。

## When to Use Subagents

Subagents work best when you need broad context from multiple areas of a codebase at once:

- **Onboarding to an unfamiliar project**: Ask subagents to map out the architecture, key entry points, and data flow in parallel.
- **Investigating cross-cutting concerns**: Have separate subagents trace authentication, logging, and error handling simultaneously.
- **Pre-edit research**: Before making changes, use subagents to gather context from related files so the main agent can make informed edits without burning through its context window.
- **Large codebases**: When reading many files sequentially would consume too much of the main agent's context, subagents let you explore broadly without that tradeoff.

对于范围很小、已知目标文件的任务，直接让 Dline 处理即可。需要跨模块调查或让不同 Profile 承担不同职责时，再使用 Subagents。
