Dline currently ships as a VS Code extension. Extension-host requests use Dline's shared network transport so proxy settings, cancellation, timeouts, and provider-attempt diagnostics stay consistent.

## Configure the VS Code proxy

Use VS Code's proxy settings for corporate HTTP or HTTPS proxies. See [Network Connections in Visual Studio Code](https://code.visualstudio.com/docs/setup/network#_proxy-server-support) for the supported settings and environment variables.

After changing proxy or certificate settings, restart VS Code so the extension host inherits the new environment.

### Custom certificate authority

If your proxy uses a private certificate authority:

1. Add the certificate to the operating system trust store when possible.
2. Set `NODE_EXTRA_CA_CERTS` to the PEM certificate file before launching VS Code when the Node.js extension host also needs the certificate.
3. Keep strict TLS validation enabled unless you are performing a temporary, isolated diagnostic.

## Troubleshooting

### Connection Timeouts

If you're experiencing connection timeouts:

1. Verify your proxy address and port are correct
2. Check if the proxy requires authentication
3. Ensure the AI provider's API endpoints aren't blocked by your firewall

### SSL/TLS Certificate Errors

If you see certificate-related errors:

1. Check that `NODE_EXTRA_CA_CERTS` points to the correct certificate file
2. Ensure the certificate file is in PEM format
3. Use curl to verify the certificate works, for example, `curl -x proxy.corp.example:8080 --cacert /path/to/ca-cert.pem -o - -vv https://api.dline.bot/`
4. Consider disabling `http.proxyStrictSSL` in VS Code only for a temporary diagnostic (not recommended for normal use)

### Testing Proxy Configuration

If you encounter problems with Dline networking, first verify your proxy
configuration works using curl:

```bash
# Linux/macOS
export https_proxy=http://proxy.company.com:8080
curl -vv https://api.anthropic.com

# Windows PowerShell
$env:https_proxy="http://proxy.company.com:8080"
curl.exe -vv https://api.anthropic.com
```

Use `--cacert $NODE_EXTRA_CA_CERTS` to specify a certificate if necessary.

Next, open **View → Output** in VS Code and inspect the Dline output for sanitized network errors. Do not paste tokens, authorization headers, or full request bodies into issue reports.

## Common Proxy Patterns

### Authenticated HTTPS Proxy

```bash
export https_proxy=http://username:password@proxy.company.com:8080
export NODE_EXTRA_CA_CERTS=/path/to/ca-cert.pem
```

### Proxy with No Authentication

```bash
export https_proxy=http://proxy.company.com:8080
export http_proxy=http://proxy.company.com:8080
```

### Proxy with Bypass Rules

```bash
export https_proxy=http://proxy.company.com:8080
export no_proxy=localhost,127.0.0.1,.company.local,192.168.0.0/16
```
