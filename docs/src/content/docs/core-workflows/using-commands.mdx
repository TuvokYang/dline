Type `/` in the input box to open suggestions grouped into built-in commands, enabled workflows and skills, and available MCP prompts. Keep typing a name to filter the list: `/rev`, for example, finds entries whose names start with `rev`.

## Automatic command prefixes

**Picking an entry adds the prefix for its type automatically; you do not need to type it yourself.** The menu shows names, while the full invocation forms are:

| Menu group | Example name | Automatically completed invocation |
| --- | --- | --- |
| **Default Commands** | `newtask` | `/cmd:newtask` |
| **Workflows** | `review` | `/workflow:review` |
| **Skills** | `review` | `/skills:review` |
| **MCP Prompts** | `server:prompt` | `/mcp:server:prompt` |

For example, with a workflow named `review` enabled, type `/rev` and pick `review` under **Workflows**. Dline uses `/workflow:review`. Add a request such as "Check error paths in these changes," then send the message. Picking the menu entry does not run it immediately.

Prefixes distinguish command types: a workflow and a skill with the same name use `/workflow:review` and `/skills:review`, respectively.

You can also type a complete invocation yourself. Built-in commands accept forms without a type prefix, such as `/newtask` and `/compact`. For workflows, skills, and MCP prompts, use the corresponding prefix or pick from the menu.

## Built-in commands

| Command | Menu text | What it does |
|---|---|---|
| `/newtask` | Create a new task with context from the current task | Has Dline summarize the current work, decisions, relevant files, problems, and next steps as the starting point of a new task |
| `/deep-planning` | Create a comprehensive implementation plan before coding | Investigates the codebase before coding, writes an implementation plan, and creates a follow-up task for the implementation |
| `/smol`, `/compact` | Condenses your current context window | Compacts the current task's context right away |
| `/newrule` | — | Creates a new rule file under `.agents/rules/` based on preferences expressed in the conversation |
| `/reportbug` | — | Drafts a problem report and opens a prefilled GitHub issue page |
| `/explain-changes` | Explain code changes between git refs (PRs, commits, branches, etc.) | Explains code changes between two Git refs, or between a ref and the working tree (VS Code only) |

### `/newtask`

Dline first drafts a handoff summary and shows it to you as a preview. You can create the new task from it or keep chatting in the current one.

Use it when the current task's context has grown long but the work needs to continue.

<span id="smol"></span>

### `/smol` and `/compact`

Both commands do the same thing: they authorize Dline to compact the **current** task's context right away, with the model writing a summary that replaces older conversation. The summary is model-written and cannot be guaranteed to keep every detail. For automatic compaction, see [Auto compact](/features/auto-compact/).

### `/newrule`

Dline creates a new Markdown rule file in the workspace's `.agents/rules/` folder based on preferences actually expressed in the conversation, without overwriting existing rules. Whether the rule applies to later tasks depends on whether it is enabled and on any conditional rule criteria; see [Rules](/customization/rules/).

### `/deep-planning`

Use this command to investigate the codebase before coding, ask clarifying questions when needed, write a plan document, and create a follow-up task for implementation. See [Plan and Act](/core-workflows/plan-and-act/#deep-planning).

### `/explain-changes`

Compares two Git refs, `from_ref` and `to_ref`; when `to_ref` is omitted, it compares against the files in the working tree. The workspace must be a Git repository, and binary files are skipped.

<Aside type="caution">
Comparing against `HEAD` includes every uncommitted change, not only staged changes.
</Aside>

### `/reportbug`

Dline works with you on the report fields such as the title, what happened, and the steps to reproduce, and adds environment details: operating system, editor, Dline version, provider, and model. After you confirm, Dline opens a prefilled GitHub issue page in your browser for you to review and submit; Dline does not submit the issue itself.

## Workflows

A workflow is a set of step-by-step instructions saved as a Markdown file; invoking it injects its content into the current task. Dline discovers workflows in:

- the workspace: `.agents/workflows/`;
- globally: `<documents-root>/workflows/` (`<documents-root>` defaults to `dline` inside your system Documents folder and can be overridden with `DLINE_DOCS_DIR`).

Picking from **Workflows** adds `/workflow:` automatically. To invoke one manually, use `/workflow:<name>` (the file name without its extension). Enable or disable individual workflows in **Manage Dline Rules & Workflows**; see [Workflows](/customization/workflows/) for authoring instructions.

## Skills

Enabled skills appear under **Skills**; picking one adds `/skills:` automatically. You can also type `/skills:<name>` to add its instructions to the current task. For how to write and store skills, see [Skills](/customization/skills/).

## MCP prompts

When a connected, enabled MCP server provides prompts, choose one under **MCP Prompts**. Dline completes `/mcp:<server-name>:<prompt-name>`, retrieves that prompt, and adds it to the current task. See [MCP](/mcp/mcp-overview/) for connecting and enabling servers.
