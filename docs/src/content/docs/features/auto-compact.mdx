长任务会不断占用模型的上下文窗口。**Auto Compact** 开启后，Dline 会在上下文接近上限时让模型总结较早的对话，用摘要代替这些内容继续任务。

## 开启

在 **Settings → Features** 中打开 **Auto Compact**（说明为 “Automatically compress conversation history.”）。该选项**默认关闭**。

## 设置项

开启后会出现以下设置：

| 设置 | 默认值 | 说明 |
|---|---|---|
| **Compression point (%)** | 97 | 可调范围 1–97，数值越小越早压缩 |
| **Minimum reserve** | 5K | 预留空间的下限（K tokens） |
| **Maximum reserve** | 30K | 预留空间的上限（K tokens） |
| **Maximum context** | 0 | 绝对上下文上限（K tokens），0 表示不设绝对上限 |

触发点并不是简单的“用到 97%”。按百分比算出的预留空间会被限制在最小与最大预留之间；如果模型的上下文窗口大于 **Maximum context**，则以该绝对值作为触发中心。Dline 还会自动加上 2K 的估算容差。

输入非法时会提示 “Reserve values must be whole numbers from 0 to …” 或 “Minimum reserve cannot exceed maximum reserve.”。

## 压缩时发生什么

1. Dline 指示模型写出摘要，涵盖用户请求、技术细节和待完成的工作。开启 [Focus Chain](/core-workflows/task-management/#focus-chain) 时，待办清单的进度也会提供给摘要。
2. 聊天中会出现 **Summary** 卡片，显示摘要生成过程和结果。
3. 之后发送给模型的内容由“累积摘要 + 尚未被摘要覆盖的消息 + 当前的继续内容”组成。

保存在磁盘上的完整对话记录不会被删除，只是发送给模型的内容变短了。

<Aside type="caution">
摘要由模型生成，可能遗漏细节。压缩之后，Dline 并不“记得所有内容”；如果某些细节很重要，可以在压缩后再次提醒它，或把关键约束写进 [Dline Rules](/customization/dline-rules/)。
</Aside>

## 恢复到压缩之前

压缩完成后，Summary 卡片旁的检查点显示为 **Compaction checkpoint**。点击 **Restore** 只提供 **Restore Task Only**：对话会回到压缩之前，工作区文件保持不变。从压缩卡片恢复时不能同时编辑消息。

## 手动压缩

无论是否开启 Auto Compact，都可以在输入框中输入 `/compact` 或 `/smol` 立即压缩当前任务，参见[使用斜杠命令](/core-workflows/using-commands/)。

## 未开启时

Auto Compact 关闭时，Dline 仍会在上下文接近上限时进行基于规则的裁剪：优化重复的文件读取，并删除较早的对话轮次，始终保留第一轮对话。这种方式不生成摘要，被删除的内容不会以任何形式保留在发送给模型的上下文中。

## 费用

生成摘要本身是一次模型请求，会产生相应的 token 用量和费用，计入任务的累计用量。具体费用取决于服务商和缓存情况。
