If you used Cline before, Dline checks for legacy Cline data at startup and copies what it can into Dline's own storage locations. Migration only copies; it never modifies or deletes Cline files.

## When it runs

- The check runs every time the extension starts. Data is copied only when at least one item has a source with content and a target that is missing or empty.
- While migrating, Dline shows the notification **Dline: Migrating legacy Cline data...** with the progress text **Copying data into empty Dline locations...**.
- When at least one item was copied, Dline shows **Dline: Data migrated - …** listing what was processed.
- Each step runs on its own. If one step fails, Dline logs the error and continues with the next step; extension startup is not blocked.

## What is migrated

The table lists the steps in execution order. `<Documents>` is the operating system's Documents directory, and `<documents-root>` is the Dline documents root, which defaults to `<Documents>/dline`.

| Order | Source | Target | Condition |
|---|---|---|---|
| 1 | `~/.cline/data/` | `~/.dline/data/` | Target is missing or empty |
| 2 | `~/.cline/endpoints.json` | `~/.dline/endpoints.json` | Target file does not exist |
| 3 | `<Documents>/Cline/settings/cline_mcp_settings.json` | `<documents-root>/settings/mcp_settings.json` | Target file does not exist |
| 4 | The rest of `<Documents>/Cline/`, excluding the top-level `tasks/` | `<documents-root>/` | The documents root is missing or empty when this step runs |
| 5 | `checkpoints/` in legacy extension storage | `<documents-root>/checkpoints/` | Target is missing or empty |
| 6 | `puppeteer/` in legacy extension storage | `~/.dline/puppeteer/` | Target is missing or empty |
| 7 | `cache/sync-queue.json` in legacy extension storage | `~/.dline/cache/sync-queue.json` | Target file does not exist |

"Legacy extension storage" is the global storage directory VS Code assigns to the `saoudrizwan.claude-dev` or `cline.cline` extension, located in the same parent directory as Dline's global storage. Steps 5–7 each use the first legacy directory that contains the corresponding item.

When deciding whether a directory is empty, Dline ignores `.DS_Store`, `Thumbs.db`, and `desktop.ini`. The targets of steps 1, 6, and 7 are always under `~/.dline`; setting `DLINE_DIR` does not change where migration writes.

## What is not migrated

**Task history is not migrated.** Both `<Documents>/Cline/tasks/` and task records in legacy extension storage stay where they are. Dline indexes tasks in SQLite and keeps per-task runtime state that a Cline task directory does not contain, so legacy tasks cannot be opened or resumed in Dline.

Migration never merges data either: when a target already has content, that item is skipped and existing Dline data is not overwritten.

## Skipping migration

Migration does not run at all when any of these is true:

| Environment variable | Effect |
|---|---|
| `DLINE_SKIP_MIGRATION=1` | Skips migration |
| `DLINE_HOME_DIR` is set | Custom paths are in use; migration is skipped |
| `DLINE_DOCS_DIR` is set | Custom paths are in use; migration is skipped |

See [Configuration](/en/getting-started/config/) for what these variables control.

## After migration

1. Open the provider settings and confirm your existing configuration is there.
2. Open the MCP server settings and confirm your servers are listed. See [MCP overview](/en/mcp/mcp-overview/).
3. Check that your global rules and workflows are visible in Dline.

## Troubleshooting

<Aside type="caution" title="Rules or workflows were not migrated">
Step 4 runs only while the documents root is still empty. If step 3 has already copied the MCP settings file, or you have run Dline before, the documents root is no longer empty and the rest of `<Documents>/Cline/` is skipped. Copy the files you need into the matching folders under `<documents-root>` by hand.
</Aside>

- **Folder names when copying by hand**: Dline's global folder names are lowercase: `rules/`, `workflows/`, `skills/`, `hooks/`, `mcp/`. Automatic migration keeps the original folder names. On a case-sensitive file system, rename a legacy folder whose casing differs (for example `Rules`) to the matching lowercase name.
- **The MCP settings file has a different name**: Cline uses `cline_mcp_settings.json`, while Dline uses `mcp_settings.json`. Rename the file when copying it by hand.
- **Migration did not run**: check whether any variable in the table above is set, and confirm that the target location is really missing or empty.
- **Keep using Cline**: migration does not touch Cline's files, so your original data stays in place.
