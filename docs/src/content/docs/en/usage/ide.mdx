This tutorial walks you through building a single-file todo app with Dline. Along the way you will use Plan and Act modes, approve changes, iterate on the result, and roll back with checkpoints.

## Prerequisites

Before starting, make sure you have:

- Dline installed in your editor (see [Installing Dline](/en/getting-started/installing-dline/));
- an AI model connected (see [Models & Providers](/en/getting-started/authorizing-with-dline/)).

## Step 1: Open a project folder

Dline creates and edits files inside your workspace. Prepare an empty folder for the todo app:

<Steps>

1. In VS Code, choose **File → Open Folder**.

2. Create a folder, for example `todo-app` on your Desktop.

3. Select the folder and choose **Open**.

</Steps>

The folder now appears in the Explorer. The file list is empty because this is a new project.

<Aside type="caution">
Without an open folder, Dline does not know where to create files. Always open a folder before starting a task.
</Aside>

## Step 2: Open the Dline panel

Select the **Dline** icon in the VS Code Activity Bar to open the panel. The input box sits at the bottom and the task conversation above it; the panel title bar provides buttons such as **New Task**, **History**, and **Settings**.

<Aside type="tip">
When no editor text is selected, press `Cmd+'` (macOS) or `Ctrl+'` (Windows/Linux) to move focus to the Dline input box. The corresponding command is **Dline: Jump to Chat Input**.
</Aside>

## Step 3: Give Dline a task

Select the input box at the bottom of the panel and paste this prompt:

```text
Build a todo app in a single HTML file. Include:
- Input field to add new tasks
- List that displays all tasks
- Checkbox to mark tasks complete (with strikethrough styling)
- Button to delete individual tasks
- Clean, modern design with CSS
- All JavaScript inline in the same file
```

Press `Enter` or select the send button. You can change the send shortcut to `Ctrl + Enter` or `Shift + Enter` in **Settings → General → Send messages with**.

## Step 4: Understand Plan mode and Act mode

The bottom-right corner of the input area has a **Plan / Act** switch. Select it to change modes; hover over it to see the toggle shortcut.

- **Plan mode**: Dline gathers information and discusses an approach with you. Use it to align on requirements, adjust the approach, and clarify details.
- **Act mode**: Dline carries out the task directly, creating files and writing code.

<Aside>
To block file edits while in Plan mode, turn on **Strict Plan Mode** in **Settings → Features** (off by default).

This tutorial needs Dline to create files, so switch to **Act** mode. For when to use each mode, see [Plan and Act](/en/core-workflows/plan-and-act/).
</Aside>

## Step 5: Approve changes

When Dline is ready to write a file, the chat shows the target path (for example `index.html`) and the proposed content, followed by two buttons:

- **Approve**: let Dline create or edit the file;
- **Reject**: decline this change; you can then give different instructions.

Select **Approve**. `index.html` appears in the Explorer on the left.

<Aside>
With the default settings, editing files requires your approval, while reading files inside the workspace and running safe commands are approved automatically. You can adjust each category in [Auto-approve](/en/features/auto-approve/).
</Aside>

## Step 6: View the app

Open `index.html` in a web browser:

<Tabs>
  <TabItem label="macOS">
    **Option A: Use the terminal**

    Open a terminal in your editor (`` Ctrl+` `` or **Terminal → New Terminal**) and run:

    ```bash
    open index.html
    ```

    **Option B: Use Finder**

    Right-click `index.html` in the Explorer, choose **Reveal in Finder**, and double-click the file.
  </TabItem>
  <TabItem label="Windows">
    **Option A: Use the terminal**

    Open a terminal in your editor (`` Ctrl+` `` or **Terminal → New Terminal**) and run:

    ```bash
    start index.html
    ```

    **Option B: Use File Explorer**

    Right-click `index.html` in the Explorer, choose **Reveal in File Explorer**, and double-click the file.
  </TabItem>
  <TabItem label="Linux">
    **Option A: Use the terminal**

    Open a terminal in your editor (`` Ctrl+` `` or **Terminal → New Terminal**) and run:

    ```bash
    xdg-open index.html
    ```

    **Option B: Use your file manager**

    Right-click `index.html` in the Explorer, choose **Open Containing Folder**, and double-click the file.
  </TabItem>
</Tabs>

If you have the Live Server extension installed, you can also right-click `index.html` and choose **Open with Live Server**; the page reloads automatically when files change.

Try adding, checking off, and deleting a few tasks. The app runs entirely in your browser with no backend.

## Step 7: Iterate on the project

Keep sending messages **in the same task**. Dline modifies the existing code instead of starting over. Try:

```text
Add local storage so tasks persist when I refresh the page
```

```text
Switch to a dark theme with purple accent colors
```

```text
Add a filter to show all, active, or completed tasks
```

Dline first reads the current `index.html`, then proposes specific changes and waits for your approval before modifying the file. Select **Approve**, then refresh the browser to see the result.

## Step 8: Undo changes with checkpoints

After Dline changes the workspace, a **Checkpoint** marker appears in the chat. Hover over the marker to reveal two buttons:

- **Compare**: show which files have changed since that checkpoint;
- **Restore**: open the restore menu.

The restore menu offers these options:

| Option | Effect |
|---|---|
| **Restore Files & Task** | Revert files to the checkpoint and clear messages after that point |
| **Restore Files Only** (under **More options**) | Revert only the files to the checkpoint and keep the conversation |
| **Restore Task Only** (under **More options**) | Clear only the messages after that point; files stay unchanged |

To undo a change but keep discussing a different approach with Dline, use **Restore Files Only**.

<Aside type="tip">
Checkpoints are stored in a shadow Git repository that Dline manages separately, so they do not affect your project's commits or branches. Checkpoints require Git to be installed; you can turn the feature on or off in **Settings → Features → Checkpoints**.
</Aside>

Learn more in [Checkpoints](/en/core-workflows/checkpoints/).

## What you learned

You have completed the core Dline workflow:

1. opened a project folder as the workspace;
2. opened the Dline panel and described a task in the input box;
3. understood and switched between Plan and Act modes;
4. approved file changes before they were written;
5. iterated by sending follow-up messages in the same task;
6. used checkpoints to undo changes.

The same patterns work for any project, from small scripts to full applications. The more specific the context you give, the better the results.

## Need help?

- **Start a new task**: type `/newtask` in the input box and Dline starts a new task with context carried over from the current one;
- **Report a problem**: type `/reportbug` and Dline helps you gather the details and file a GitHub issue;
- **Project issues**: visit the [Dline issue tracker](https://github.com/TuvokYang/Dline/issues).
