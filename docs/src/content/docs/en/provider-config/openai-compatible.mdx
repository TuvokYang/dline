Many model providers expose an API that is compatible with OpenAI's, for example Together AI, Perplexity, self-hosted gateways, and Azure OpenAI. Dline connects to them through the **OpenAI** provider with a custom base URL.

For the official OpenAI API, see [OpenAI / ChatGPT subscription](/en/provider-config/openai/). Ollama and LM Studio have dedicated providers; see [Running models locally](/en/running-models-locally/overview/).

## Basic setup

You need three pieces of information:

- **Base URL**: the provider's API address, not `https://api.openai.com/v1`.
- **API key**: the secret key issued by that provider.
- **Model ID**: the identifier of the model you want to use.

<Steps>

1. Click the **Settings** button in the Dline panel title bar.

2. Set **API Provider** to **OpenAI**.

3. Check **Use custom base URL** and enter the provider's API address.

4. Paste the provider's key into the **OpenAI API Key** field.

5. Select a model under **Model**. If the model is not listed, check **Use custom model ID** and type it under **Model ID**.

</Steps>

<Aside>
Model IDs differ between providers. Always check the provider's documentation.
</Aside>

## Advanced options

- **API Format:** choose the request format; it must match a format the endpoint supports.
- **Model Configuration:** set max output tokens, context window, image support, tool support, and input / output prices for a custom model, so Dline can choose the right prompt profile and calculate cost.
- **Custom Headers:** click **Add Header** to add any extra request headers the provider requires.
- **Use explicit prompt cache controls:** enable this only when the endpoint supports `prompt_cache_breakpoint`. If the controls are rejected, the current task falls back to automatic caching.

## Azure OpenAI

- Enter your Azure OpenAI resource address under **Use custom base URL**.
- To pin an API version, check **Set Azure API version** and enter it. The default is `2024-10-01-preview`.
- Check **Use Azure Identity Authentication** to reuse an existing Azure managed identity. It does not start a sign-in; it only reuses an existing authentication state, such as `az login`.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| Invalid API key | Check that the key is correct and belongs to the provider behind the current base URL. |
| Model not found | Check that the model ID is valid and available at the current base URL. |
| Connection errors | Check the base URL, whether this machine can reach the service, and your firewall and proxy settings. See [Networking and proxies](/en/troubleshooting/networking-and-proxies/). |
| Unexpected output | Try another model, or check that the capabilities in **Model Configuration** match the model. |
