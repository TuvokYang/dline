本教程带你用 Dline 从零构建一个单文件待办应用，并在过程中熟悉 Plan/Act 模式、审批改动、迭代修改和检查点回滚。

## 准备工作

开始之前，请确认：

- 已在编辑器中安装 Dline（参见[安装 Dline](/zh-cn/getting-started/installing-dline/)）；
- 已连接一个 AI 模型（参见[模型与服务商](/zh-cn/getting-started/authorizing-with-dline/)）。

## 第 1 步：打开项目文件夹

Dline 在工作区中创建和编辑文件。为待办应用准备一个空文件夹：

<Steps>

1. 在 VS Code 中选择 **File → Open Folder**。

2. 新建一个文件夹，例如桌面上的 `todo-app`。

3. 选中该文件夹并点击 **Open**。

</Steps>

资源管理器中会显示该文件夹，此时文件列表为空。

<Aside type="caution">
没有打开文件夹时，Dline 不知道应该在哪里创建文件。开始任务前请先打开一个文件夹。
</Aside>

## 第 2 步：打开 Dline 面板

点击 VS Code 活动栏中的 **Dline** 图标即可打开面板。面板分为三块：顶部标题栏、中间的任务对话、底部的输入框。

### 面板标题栏

标题栏按钮与是否有任务在运行无关，随时可用：

![Dline 面板标题栏及编号标注的按钮](@docs-assets/ui/panel-title-bar.png)

| 编号 | 按钮 | 作用 |
|---|---|---|
| 1 | **New Task**（`+`） | 在当前编辑器旁边的编辑器标签页中打开一个新的 Dline 任务；侧边栏和其他标签页中的任务不受影响 |
| 2 | **MCP Servers** | 侧边栏切换到 MCP 服务器视图 |
| 3 | **History** | 侧边栏切换到任务历史，可重新打开、搜索和删除任务 |
| 4 | **Account** | 侧边栏切换到账户视图 |
| 5 | **Settings** | 侧边栏切换到设置，包括 Profile、功能开关和终端选项 |

### 任务头

打开任务后，对话顶部会显示任务头。点击折叠箭头或任务标题可以展开或收起。

![展开后的任务头及编号标注的控件](@docs-assets/ui/task-header.png)

| 编号 | 控件 | 作用 |
|---|---|---|
| 1 | 用量胶囊（`In`、`Out`、`RPM`、`TPM`、`Hit`、费用） | 显示 token 用量、请求速率、提示缓存命中率和费用（模型有定价时）；点击打开 **API Rate History** |
| 2 | 上下文条 | 显示任务的上下文窗口占用，悬停可查看摘要 |
| 3 | **Compact Task** | 压缩对话以释放上下文，执行前会先确认 |
| 4 | **Copy Text** | 复制任务提示词 |
| 5 | **Refresh Prompt Cache** | 重建任务的系统提示词。出现警告图标表示任务开始后 Rules、Skills、MCP 服务器等提示词输入发生了变化；刷新会导致一次提示缓存未命中 |
| 6 | **Delete Task** | 确认后永久删除任务 |
| 7 | **Close Task**（`×`） | 关闭当前任务，回到起始界面 |

自动压缩失败且 **Retry** 无法恢复任务时，**Compact Task** 旁会出现 **More context actions**（`⋯`）按钮，提供 **Force truncate conversation history**，需要输入 `TRUNCATE` 确认。

任务头下方有时会出现提示横幅，例如提示缓存命中率持续偏低、检查点出错（**Retry Checkpoints** / **Disable Checkpoints**），或任务锁被其他窗口占用（**Unlock**）。

### 输入区

输入框上方是 **Auto-approve** 栏，下方是一排工具按钮：

![Dline 输入区：上方为 Auto-approve 栏，下方为编号标注的工具按钮](@docs-assets/ui/chat-input-toolbar.png)

| 编号 | 控件 | 作用 |
|---|---|---|
| 1 | **@**（Add Context） | 插入 `@` 引用文件、文件夹、终端输出、Problems 等上下文 |
| 2 | **+**（Add Files & Images） | 选择文件或图片附加到消息 |
| 3 | MCP 图标（Manage MCP Servers） | 打开 MCP 服务器弹窗，启用或停用服务器 |
| 4 | 天平图标（Manage Dline Rules & Workflows） | 打开能力面板，管理 Rules、Workflows、Skills、Subagents 与 Environments |
| 5 | 模型名称（Select model） | 切换当前使用的模型 |
| 6 | **Plan / Act** 开关 | 在 Plan 模式与 Act 模式之间切换 |
| 7 | 发送按钮 | 发送消息 |

<Aside type="tip">
在编辑器中未选中文本时，按 `Cmd+'`（macOS）或 `Ctrl+'`（Windows/Linux）可以把焦点移到 Dline 输入框；对应命令是 **Dline: Jump to Chat Input**。
</Aside>

## 第 3 步：给 Dline 一个任务

点击面板底部的输入框，粘贴以下提示词：

```text
Build a todo app in a single HTML file. Include:
- Input field to add new tasks
- List that displays all tasks
- Checkbox to mark tasks complete (with strikethrough styling)
- Button to delete individual tasks
- Clean, modern design with CSS
- All JavaScript inline in the same file
```

按 `Enter` 或点击发送按钮提交。发送快捷键可在 **Settings → General → Send messages with** 中改为 `Ctrl + Enter` 或 `Shift + Enter`。

## 第 4 步：理解 Plan 模式与 Act 模式

输入区右下角有一个 **Plan / Act** 切换开关，点击即可切换模式；把鼠标悬停在开关上可以看到切换快捷键。

- **Plan 模式**：Dline 收集信息并与你讨论方案。适合先对齐需求、调整思路、澄清细节。
- **Act 模式**：Dline 直接执行任务，创建文件、编写代码。

![点击 Plan / Act 开关在两种模式之间切换](@docs-assets/ui/docs-mode-switch.gif)

<Aside>
如果希望在 Plan 模式下强制禁止文件编辑，请在 **Settings → Features** 中开启 **Strict Plan Mode**（默认关闭）。

本教程需要 Dline 创建文件，请切换到 **Act** 模式。何时使用哪种模式，参见 [Plan 与 Act](/zh-cn/core-workflows/plan-and-act/)。
</Aside>

## 第 5 步：审批改动

Dline 准备写入文件时，聊天中会显示目标文件路径（例如 `index.html`）和拟写入的内容，下方出现两个按钮：

- **Approve**：允许 Dline 创建或编辑该文件；
- **Reject**：拒绝本次改动，你可以随后给出新的指示。

点击 **Approve**，`index.html` 会出现在编辑器左侧的资源管理器中。

![Dline 提出写入文件，点击 Approve 后文件被创建，任务完成](@docs-assets/marketplace/r1-hero.gif)

<Aside>
默认配置下，编辑文件需要你手动批准；读取工作区内的文件、执行安全命令等操作会自动批准。你可以在[自动批准](/zh-cn/features/auto-approve/)中按类别调整。
</Aside>

## 第 6 步：查看应用

在浏览器中打开 `index.html`：

<Tabs>
  <TabItem label="macOS">
    **方式 A：使用终端**

    在编辑器中打开终端（`` Ctrl+` `` 或菜单 **Terminal → New Terminal**），执行：

    ```bash
    open index.html
    ```

    **方式 B：使用 Finder**

    在资源管理器中右键 `index.html`，选择 **Reveal in Finder**，然后双击该文件。
  </TabItem>
  <TabItem label="Windows">
    **方式 A：使用终端**

    在编辑器中打开终端（`` Ctrl+` `` 或菜单 **Terminal → New Terminal**），执行：

    ```bash
    start index.html
    ```

    **方式 B：使用文件资源管理器**

    在资源管理器中右键 `index.html`，选择 **Reveal in File Explorer**，然后双击该文件。
  </TabItem>
  <TabItem label="Linux">
    **方式 A：使用终端**

    在编辑器中打开终端（`` Ctrl+` `` 或菜单 **Terminal → New Terminal**），执行：

    ```bash
    xdg-open index.html
    ```

    **方式 B：使用文件管理器**

    在资源管理器中右键 `index.html`，选择 **Open Containing Folder**，然后双击该文件。
  </TabItem>
</Tabs>

如果安装了 Live Server 扩展，也可以右键 `index.html` 并选择 **Open with Live Server**，文件变化时页面会自动刷新。

试着添加、勾选和删除几个任务。应用完全在浏览器中运行，不需要后端。

## 第 7 步：迭代改进

在**同一个任务**中继续发送消息，Dline 会基于已有代码修改，而不是从头重写。可以尝试：

```text
Add local storage so tasks persist when I refresh the page
```

```text
Switch to a dark theme with purple accent colors
```

```text
Add a filter to show all, active, or completed tasks
```

Dline 会先读取现有的 `index.html`，再提出具体改动，并在修改前等待你的批准。点击 **Approve** 后刷新浏览器即可看到效果。

## 第 8 步：用检查点撤销改动

Dline 修改工作区后，聊天中会出现 **Checkpoint** 标记。把鼠标悬停在标记上会显示两个按钮：

- **Compare**：查看从该检查点起发生了哪些文件变化；
- **Restore**：打开恢复菜单。

恢复菜单提供以下选项：

| 选项 | 效果 |
|---|---|
| **Restore Files & Task** | 将文件恢复到该检查点，并清除该点之后的消息 |
| **Restore Files Only**（在 **More options** 中） | 只将文件恢复到该检查点，保留对话 |
| **Restore Task Only**（在 **More options** 中） | 只清除该点之后的消息，文件保持不变 |

想撤销某次改动但继续和 Dline 讨论其他做法时，使用 **Restore Files Only**。

<Aside type="tip">
检查点保存在 Dline 独立管理的影子 Git 仓库中，不会影响你项目中的提交和分支。使用检查点需要本机已安装 Git；可在 **Settings → Features → Checkpoints** 中开关该功能。
</Aside>

更多内容参见[检查点](/zh-cn/core-workflows/checkpoints/)。

## 你学到了什么

你已经完成了 Dline 的核心工作流程：

1. 打开项目文件夹作为工作区；
2. 打开 Dline 面板并在输入框中描述任务；
3. 理解并切换 Plan 与 Act 模式；
4. 在写入前审批文件改动；
5. 在同一任务中发送后续消息进行迭代；
6. 使用检查点撤销改动。

这些模式适用于从简单脚本到完整应用的各种项目。你提供的上下文越具体，结果越好。

## 需要帮助？

- **开启新任务**：在输入框中输入 `/newtask`，Dline 会基于当前上下文开启一个新任务；
- **报告问题**：输入 `/reportbug`，Dline 会协助整理并创建 GitHub issue；
- **项目 issue**：访问 [Dline issue tracker](https://github.com/TuvokYang/Dline/issues)。
