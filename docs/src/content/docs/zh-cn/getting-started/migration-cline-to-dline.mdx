Dline 不会自动导入 Cline 的数据。它从空的 Dline 文件夹开始，不会读取、修改或删除任何 Cline 文件。如果想保留 Cline 的配置，请按下文手动复制到 Dline 的文件夹。

## 开始之前

1. 关闭所有 VS Code 窗口，避免复制期间 Cline 或 Dline 正在写入文件。
2. 找到本机上的对应文件夹。`<Documents>` 指操作系统的“文档”目录。

| 文件夹 | Cline | Dline |
|---|---|---|
| 数据根目录：设置、全局状态、密钥 | `~/.cline/data/` | `~/.dline/data/`；设置了 `DLINE_DIR` 时为 `<DLINE_DIR>/data/` |
| 文档根目录：规则、工作流、技能、hooks、MCP | `<Documents>/Cline/` | `<Documents>/dline/`；设置了 `DLINE_DOCS_DIR` 时为该变量指定的目录 |
| Endpoint 配置 | `~/.cline/endpoints.json` | `~/.dline/endpoints.json` |

这些变量的作用见[配置](/zh-cn/getting-started/config/)。

<Aside type="caution">
只在 Dline 的目标文件夹不存在或为空时复制。把 Cline 文件合并进 Dline 已经用过的文件夹，可能覆盖 Dline 的设置、Profile 或凭据，事后也无法区分哪些来自 Cline。
</Aside>

## 可以复制的内容

| 内容 | 复制来源 | 复制目标 |
|---|---|---|
| 设置、全局状态和已保存的凭据 | `~/.cline/data/` 中的全部内容 | Dline 数据根目录 |
| Endpoint 配置 | `~/.cline/endpoints.json` | `~/.dline/endpoints.json` |
| MCP 服务器 | `<Documents>/Cline/settings/cline_mcp_settings.json` | Dline 文档根目录下的 `settings/mcp_settings.json`（注意文件名不同） |
| 全局规则、工作流、技能和 hooks | `<Documents>/Cline/` 中对应的目录 | Dline 文档根目录中对应的目录 |

Dline 的全局目录名是小写的：`rules/`、`workflows/`、`skills/`、`hooks/`、`mcp/`。在区分大小写的文件系统上，如果 Cline 目录名的大小写不同（例如 `Rules`），需要改成对应的小写名称。

## 无法带过来的内容

- **任务历史。** 不要复制 `<Documents>/Cline/tasks/` 或 Cline 扩展存储中的任务记录。Dline 用 SQLite 索引任务，并保存 Cline 任务目录中没有的每任务运行时状态，因此 Cline 任务无法在 Dline 中打开或恢复。
- **Checkpoint、浏览器数据和缓存。** 它们属于 Cline 任务，Dline 会按需重新生成。

## 复制之后

1. 启动 VS Code 并打开 Dline。
2. 打开服务商设置，确认原有配置都在。
3. 打开 MCP 服务器设置，确认服务器都已列出。参见 [MCP 概览](/zh-cn/mcp/mcp-overview/)。
4. 检查全局规则和工作流在 Dline 中可见。

Cline 的文件仍保留在原位置，你可以同时继续使用 Cline。
