[Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/what-is-bedrock.html) 是 AWS 提供的全托管服务，可以通过 AWS 调用 Anthropic Claude、Amazon Nova 等主流生成式模型。本页适合希望用 Bedrock API Key 快速接入的个人开发者。

其他认证方式见 [IAM 凭证](/zh-cn/provider-config/aws-bedrock/iam-credentials/)和 [AWS CLI Profile](/zh-cn/provider-config/aws-bedrock/cli-profile/)。

## 第 1 步：创建 Bedrock API Key

详细说明见 [AWS 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys.html)。

<Steps>

1. 登录 [AWS 管理控制台](https://aws.amazon.com/console/)。

2. 打开 [Bedrock 控制台](https://console.aws.amazon.com/bedrock)，创建一个长期有效的 API Key。该 Key 默认附带 [`AmazonBedrockLimitedAccess`](https://docs.aws.amazon.com/bedrock/latest/userguide/security-iam.html) IAM 策略。

</Steps>

### 可选：使用最小权限策略

`AmazonBedrockLimitedAccess` 权限较宽。如果希望遵循最小权限原则，Dline 调用模型只需要以下权限：

- `bedrock:InvokeModel`
- `bedrock:InvokeModelWithResponseStream`
- `bedrock:CallWithBearerToken`

<Steps>

1. 在 AWS IAM 控制台中新建策略。

2. 在 JSON 编辑器中填入以下策略：

   ```json
   {
     "Version": "2012-10-17",
     "Statement": [
       {
         "Effect": "Allow",
         "Action": ["bedrock:InvokeModel", "bedrock:InvokeModelWithResponseStream", "bedrock:CallWithBearerToken"],
         "Resource": "*"
       }
     ]
   }
   ```

   为了更安全，可以把 `Resource` 限定为具体的模型 ARN。

3. 为策略命名（例如 `DlineBedrockInvokeAccess`），并附加到 API Key 对应的 IAM 用户上。IAM 用户名与 API Key 使用相同的前缀。

</Steps>

<Aside>
- **模型列表：** 以上最小权限足以调用模型。如果希望 Dline 动态列出可用的 Bedrock 模型，可能还需要 `bedrock:ListFoundationModels` 等权限。
- **第三方模型：** `AmazonBedrockLimitedAccess` 已包含通过 AWS Marketplace 订阅第三方模型的权限，无需额外开通。Anthropic 模型仍需在控制台提交首次使用（FTU）表单。如果 Dline 提示 `Model use case details have not been submitted for this account`，请打开 [Bedrock Playground](https://console.aws.amazon.com/bedrock/home?#/text-generation-playground)，选择任意 Anthropic 模型并填写表单（可能需要先发送一条提示）。
</Aside>

## 第 2 步：确认区域

- Bedrock 在多个区域可用，请根据延迟和合规要求选择区域，参见 [AWS 全球基础设施](https://aws.amazon.com/about-aws/global-infrastructure/regions_az/)。
- 部分模型只能通过[推理配置文件](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html)调用。遇到这种情况时，在 Dline 中勾选 **Use cross-region inference**。

## 第 3 步：配置 Dline

尚未安装 Dline 时，先参阅[安装 Dline](/zh-cn/getting-started/installing-dline/)。

<Steps>

1. 点击 Dline 面板标题栏的 **Settings** 按钮。

2. 在 **Provider** 中选择 **Amazon Bedrock**。

3. 认证方式选择 **API Key**，把 Key 粘贴到 **AWS Bedrock Api Key** 输入框。

4. 在 **AWS Region** 中选择或输入区域，例如 `us-east-1`。

5. 在 **Model** 中选择模型；列表中没有目标模型时选择 **Custom** 并输入模型 ID。

6. 发送一条简单的提示测试连接，例如“写一个判断质数的 Python 函数”。

</Steps>

## 第 4 步：安全与运维建议

- **访问安全：** 尽量使用 AWS SSO 或联合身份角色，而不是长期有效的 API Key，参见 [IAM 最佳实践](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html)。
- **网络安全：** 可以配置 [AWS PrivateLink](https://docs.aws.amazon.com/vpc/latest/userguide/endpoint-services-overview.html)，并在 Dline 中勾选 **Use custom VPC endpoint** 填写终端节点地址。
- **监控：** 启用 CloudTrail 记录 Bedrock API 调用，使用 CloudWatch 监控调用次数、延迟和 token 用量，并为异常活动设置告警。
- **成本：** 使用 AWS Cost Explorer 并设置账单告警，参见 [AWS 成本管理](https://docs.aws.amazon.com/cost-management/latest/userguide/what-is-aws-cost-management.html)。
- **审计：** 定期检查 IAM 角色和 CloudTrail 日志，遵循组织内部的数据隐私与治理策略。
