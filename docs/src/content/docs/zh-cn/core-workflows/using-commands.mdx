在输入框中输入 `/`，会弹出建议菜单，按类型列出内置命令、已启用的工作流和技能，以及可用的 MCP 提示词。继续输入名称可以筛选，例如 `/rev` 会筛选名称以 `rev` 开头的条目。

## 自动补齐调用前缀

**从菜单中选择条目时，Dline 会按类型自动补齐前缀，不需要你手工输入。** 菜单显示的是名称，实际调用形式如下：

| 菜单分组 | 名称示例 | 自动补齐后的调用形式 |
| --- | --- | --- |
| **Default Commands** | `newtask` | `/cmd:newtask` |
| **Workflows** | `review` | `/workflow:review` |
| **Skills** | `review` | `/skills:review` |
| **MCP Prompts** | `server:prompt` | `/mcp:server:prompt` |

例如，已经启用名为 `review` 的工作流时，输入 `/rev`，在 **Workflows** 中选择 `review`，Dline 就会使用 `/workflow:review`。你可以接着填写“检查这次修改中的错误路径”，再发送消息。选择菜单项不会立即执行。

前缀用于区分命令类型：同名的工作流和技能分别使用 `/workflow:review` 与 `/skills:review`。

也可以直接手工输入完整调用形式。内置命令还支持 `/newtask`、`/compact` 等不带类型前缀的写法；调用工作流、技能或 MCP 提示词时，使用对应前缀，或直接从菜单选择。

## 内置命令

| 命令 | 菜单说明 | 作用 |
|---|---|---|
| `/newtask` | Create a new task with context from the current task | 让 Dline 总结当前工作、已做的决定、相关文件、遇到的问题和下一步，作为新任务的起点 |
| `/deep-planning` | Create a comprehensive implementation plan before coding | 在编码前调研代码库、写出实现计划，并创建用于实施的后续任务 |
| `/smol`、`/compact` | Condenses your current context window | 立即压缩当前任务的上下文 |
| `/newrule` | — | 根据对话中体现的偏好，在 `.agents/rules/` 下新建一个规则文件 |
| `/reportbug` | — | 整理问题报告，并打开预填内容的 GitHub issue 页面 |
| `/explain-changes` | Explain code changes between git refs (PRs, commits, branches, etc.) | 解释两个 Git 引用之间，或某个引用与工作区之间的代码变化（仅 VS Code） |

### `/newtask`

Dline 会先生成一份交接摘要并展示给你预览。你可以据此创建新任务，也可以选择继续当前对话。

适合在当前任务上下文已经很长、但工作还要继续时使用。

### `/smol` 与 `/compact`

两个命令效果相同：授权 Dline 立即对**当前**任务执行上下文压缩，由模型写出摘要来替代较早的对话。摘要由模型生成，不能保证保留所有细节。自动触发的压缩参见[自动压缩](/zh-cn/features/auto-compact/)。

### `/newrule`

Dline 会根据对话中实际表达过的偏好，在工作区的 `.agents/rules/` 目录下创建一个新的 Markdown 规则文件，不会覆盖已有规则。规则是否在后续任务中生效，取决于它是否启用以及条件规则的匹配情况，参见 [Rules](/zh-cn/customization/rules/)。

### `/deep-planning`

在编码前用这个命令调研代码库，必要时提出澄清问题，再写出计划文档并创建用于实施的后续任务。详见 [Plan 与 Act](/zh-cn/core-workflows/plan-and-act/#deep-planning)。

### `/explain-changes`

比较 `from_ref` 与 `to_ref` 两个 Git 引用；省略 `to_ref` 时与当前工作区文件比较。要求工作区是 Git 仓库，二进制文件会被跳过。

<Aside type="caution">
与 `HEAD` 比较时包含所有未提交的改动，而不只是已暂存（staged）的改动。
</Aside>

### `/reportbug`

Dline 会和你一起整理问题标题、现象、复现步骤等字段，并自动补充操作系统、编辑器、Dline 版本、服务商和模型等环境信息。你确认后，Dline 会在浏览器中打开一个预填好内容的 GitHub issue 页面，由你检查并提交；Dline 不会替你直接提交 issue。

## 工作流

工作流是保存为 Markdown 文件的一组步骤说明，调用时其内容会注入到当前任务中。Dline 会从以下位置发现工作流：

- 工作区：`.agents/workflows/`；
- 全局：`<documents-root>/workflows/`（`<documents-root>` 默认是系统“文档”目录下的 `dline`，可用 `DLINE_DOCS_DIR` 覆盖）。

从 **Workflows** 菜单选择时，Dline 自动补齐 `/workflow:`；手工调用时使用 `/workflow:<名称>`（文件名不含扩展名）。可以在 **Manage Dline Rules & Workflows** 中启用或停用某个工作流，编写方式参见[工作流](/zh-cn/customization/workflows/)。

## 技能

已启用的技能会出现在 **Skills** 菜单中，选择时自动补齐 `/skills:`。也可以手工输入 `/skills:<名称>`，把该技能的说明加入当前任务。技能的编写与存放位置参见[技能](/zh-cn/customization/skills/)。

## MCP 提示词

已连接且启用的 MCP 服务器提供提示词时，可在 **MCP Prompts** 菜单中选择，Dline 会自动补齐 `/mcp:<服务器名>:<提示词名>`。这会取得该提示词并加入当前任务；MCP 的连接与启用方式参见 [MCP](/zh-cn/mcp/mcp-overview/)。
