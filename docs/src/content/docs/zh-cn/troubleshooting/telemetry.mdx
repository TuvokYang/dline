Dline 把“使用数据”和“错误报告”分开征求同意。未经你同意，不会发送任何一类数据。

## 同意设置

在 **Settings → About** 中有两个独立的选项：

- **Allow usage reporting**：使用数据；
- **Allow error reporting**：错误报告。

两者默认都未勾选。只有明确勾选才算同意；未勾选（包括从未设置过）时，对应类别的数据不会被收集或发送。组织的远程配置可以关闭遥测，但不能替你开启。

VS Code 自身的遥测设置（`telemetry.telemetryLevel`）关闭时，Dline 也不会向远程端点发送遥测数据。

## 数据发往哪里

- 默认情况下，同意后的数据以 OpenTelemetry（OTLP，HTTP/protobuf）格式发送到**本机**的 `http://127.0.0.1:4318`。只有你在本机运行了 OTLP 收集器时，这些数据才会被接收。
- 组织可以通过远程配置指定其他 OTLP 端点。
- 同意后，Dline 还会在本地写入 JSONL 格式的会话日志，用于诊断。

<Aside>
Dline 默认不会把遥测数据发送到任何固定的外部服务。
</Aside>

## 哪些内容会被屏蔽

发送前，Dline 会屏蔽以下内容：

- 提示词、命令和命令输出；
- 凭据；
- 与身份相关的字段。

保留的内容包括服务商与模型名称、token 用量等数值，以及其他有长度限制的结构化字段。

<Aside type="caution">
同意后发送的事件包含一个匿名的设备标识（`distinct_id`），用于区分不同的安装，它不会被屏蔽。请不要认为遥测数据中完全没有任何标识符。
</Aside>

## 导出诊断包

勾选 **Allow error reporting** 后，**Settings → About** 中会出现 **Export diagnostic bundle**。它会在本地生成一个 ZIP 文件，写入前会再次执行脱敏处理，不会自动上传。遇到问题时，你可以检查后再决定是否附在 issue 中。
