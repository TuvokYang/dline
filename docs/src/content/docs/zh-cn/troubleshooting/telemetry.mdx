Dline 分别征求使用统计和错误诊断的同意。**Settings → About** 中的两个勾选框决定实际级别，但两者相互独立。

## 上报级别

打开 **Settings → About**，可以看到 **Allow usage reporting** 和 **Allow error reporting**。两者默认勾选。取消任一项会立即停止该通道，值为 `unset` 时同样视为关闭。

| 实际级别 | 使用统计 | 错误诊断 | 覆盖内容 |
|---|---|:--:|---|
| **级别 0：关闭** | 关 | 关 | 数据不会离开本机。仅保留一份很小的本地进程记录，用于崩溃恢复。 |
| **级别 1：使用统计** | 开 | 关 | 不含正文的计数：Dline 和模型的使用频率、请求与工具的结果、token 与缓存用量。 |
| **级别 2：错误诊断** | 关 | 开 | 崩溃、异常、健康告警和生命周期信号，并允许手动导出本地诊断包。 |
| **级别 3：使用统计 + 错误诊断** | 开 | 开 | 上述两项。两者都不包含提示词、文件、命令、模型响应或原始产物。 |

组织策略可以把任一通道强制关闭，但不能替你打开。VS Code 的 `telemetry.telemetryLevel` 可以进一步收紧，但不会放宽你在这里允许的范围。

账户属于独立通道，跟随使用统计的同意，且不会附加到普通的使用统计或诊断记录上。

### 实验性功能的遥测要求

普通发行版参与灰度需要同时开启 **Allow usage reporting** 和 **Allow error reporting**，并让 VS Code、VSCodium 等宿主实际允许全部遥测（`telemetry.telemetryLevel` 为 `all`）。完整参与条件与功能入口见[实验性功能](/zh-cn/features/experimental/)。

## 会上报什么

**使用统计**只包含有限的维度和数字：Dline 版本、编辑器与操作系统类型、服务商与模型名称、任务与工具的结果、耗时、重试次数，以及 token 和缓存用量。它不包含你的对话、文件内容、路径或命令。

**错误诊断**只包含失败与健康信号：异常类型和安全错误码、严重度、生命周期原因、CPU、内存与队列指标，以及上一次进程非正常结束的证据。硬崩溃或 `SIGKILL` 不保证能留下可用的调用栈。

自定义模型与服务商 ID 会按你填写的内容上报。不要把账号、客户名、仓库名或密钥写进自定义模型 ID。

## 数据发往何处

- 规范化的事件、指标和链路记录可以以 JSONL 形式写在本地。
- 默认网络目的地是本地端点 `http://127.0.0.1:4318`。
- 开启使用统计时，聚合后的使用计数会发往 `https://otel.dline.cc`；开启错误诊断时，聚合后的错误与运行时诊断也会发往该服务。其他通道不会使用该服务，也没有其他目的地回退到它。
- 组织配置的端点只接收你同意的使用统计信号。


## 设备标识

Dline 用一份随机设备密钥标识你的安装。它在首次发送时创建，以仅所有者可读写的权限保存在 Dline 数据根目录下。登录、退出或切换账户都不会改变它，它也不会被当作你的账户身份使用。发往 `otel.dline.cc` 的数据同时排除设备标识和账户。

## 关闭上报

当投递条件不再满足时，Dline 会中止当前发送，并删除该通道尚未发送的数据和本地访问令牌。设备密钥会保留，因此重新开启时不会注册成新设备。

取消勾选会删除该通道尚未发送的记录，但不会删除服务端已接收的数据。使用统计与错误诊断互不影响。

## 诊断包与 `/reportbug`

在开启错误诊断时，**Export diagnostic bundle** 会在本地生成一个经过脱敏的 ZIP。它不会自动上传；附加到任何地方之前请先检查内容。

当前的 `/reportbug` 处理程序会要求填写 `api_request_output` 和 `additional_context`，并在 Dline 的审批预览中显示两者。你批准后，`api_request_output` 会被填入预置的 GitHub Issue 表单，并通过浏览器 URL 传递。在你检查该表单并提交之前，GitHub 不会收到任何内容；你可以先编辑或删除该字段。这种方式不会向 `otel.dline.cc` 发送数据，也不会上传日志或 ZIP 文件。

Issue 专属的限时诊断授权尚未提供。此类诊断需要你主动请求并单独授权，且不包含提示词、代码、命令文本、模型输出、凭据或原始产物。

这些选择背后的政策见 [Dline 隐私政策](/zh-cn/privacy/)。
