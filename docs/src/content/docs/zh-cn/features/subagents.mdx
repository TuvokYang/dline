子代理（Subagent）是主任务派出的独立工作者。每个子代理有自己的上下文，只把最终结论交回主任务，因此大量的读取和搜索过程不会占满主任务的上下文。

## 开启与并发

具名子代理的开关与 Rules、Skills 一样，按任务、工作区和全局三层保存。参见[能力开关作用域](/zh-cn/customization/capability-scopes/)。

- 子代理默认开启，可在 **Settings → Features** 的 Agent 分组中通过 **Subagents** 开关关闭。
- 开关下方的 **Max Parallel Subagents** 控制同时运行的子代理数量，范围 1–64，默认 64。
- 单次批量委派最多包含 32 个子代理；超出并发上限的部分会排队等待。
- 未指定超时时，每个子代理最长运行 1200 秒（20 分钟）。

## Dline 如何委派

Dline 有两个委派工具：

- `use_subagent`：运行一个默认或具名子代理；
- `use_subagents`：一次运行 1–32 个子代理，每一项都可以单独指定具名代理、Profile 和超时。

Dline 会根据任务自行决定是否委派，你也可以在提示词中明确要求，例如：

```text
用子代理分别调查认证流程、数据库模型定义和测试配置，都只读，不修改文件。
```

每个子代理最好只回答一个明确的问题。问题之间互不依赖时才适合并行；最后由主任务核对证据并整合结论。

## 默认子代理（default.yml）

内置的默认子代理只能使用以下工具：

`read_file`、`list_files`、`search_files`、`list_code_definition_names`、`load_skill`，以及用于交回结果的 `attempt_completion`。

它不能执行命令、写文件、联网、使用浏览器或 MCP。需要这些能力时，请使用具名子代理并显式授权。

全局子代理目录中没有任何 `.yml` / `.yaml` 文件时，Dline 会自动创建一份可编辑的 `<documents-root>/subagents/default.yml`，内容就是上面的默认配置；已有文件时不会覆盖。

## 具名子代理（agent YAML）

具名子代理是一个带 frontmatter 的 YAML 文件，每个文件定义一个子代理，文件名可以任取（例如 `code-researcher.yml`），按 `name` 字段匹配，不区分大小写：

| 位置 | 作用范围 |
|---|---|
| `.agents/subagents/` | 当前工作区 |
| `<documents-root>/subagents/` | 全局（`<documents-root>` 默认是系统“文档”目录下的 `dline`，可用 `DLINE_DOCS_DIR` 覆盖） |

扩展名可以是 `.yml` 或 `.yaml`。工作区与全局有同名代理时，工作区的优先。

```yaml
---
name: code-researcher
description: Read-only codebase research
profile: "Fast Research"
tools:
  - read_file
  - list_files
  - search_files
  - list_code_definition_names
maxOutputTokens: 0.05
# 可选的能力选择，省略字段即不选择：
# rules:
#   - scope: workspace
#     path: engineering-guide.md
# skills:
#   - use-vitest
# workflows:
#   - e2e-validation
# mcp:
#   - server: github
#     tools:
#       - search_issues
#     resources:
#       - repository://instructions
---
Trace the requested code paths without changing files. Return findings with file paths, evidence, and open questions.
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 代理名称 |
| `description` | 是 | 职责说明 |
| 正文 | 是 | frontmatter 之后的内容就是子代理的提示词，不能为空 |
| `profile` | 否 | 使用哪个 API Profile，见下文 |
| `tools` | 否 | 允许的工具，数组或逗号分隔字符串。省略或为空时使用默认工具集 |
| `maxOutputTokens` | 否 | 最终结果的 token 预算，见下文 |

缺少必填字段、frontmatter 格式错误、正文为空、出现未知或空白的工具名，或输出预算非法时，该文件会被跳过并记录日志。配置模型请使用 `profile`；`modelId` 等其他字段不会生效。

`tools` 中的提问、计划、结束任务类工具（`attempt_completion` 除外）以及 `use_subagent`、`use_subagents` 会被自动移除：子代理没有可以回答问题的用户，也不能再委派子代理。`attempt_completion` 总会被授予。

具名子代理可以通过 `tools` 显式申请写文件、执行命令、联网、MCP 或生成图片等工具；这些工具仍受底层功能开关和权限约束。

## 选择 Rules、Skills、Workflows 与 MCP

具名子代理独立选择 Rules、Skills、Workflows 与 MCP 条目。每个子代理从自己的全局与工作区能力目录中选择；主任务已选项、可见目录和工具白名单既不是上限，也不会自动成为子代理的选择。父任务未选而子代理已选的能力，子代理可以使用；父任务已选而子代理未选的，不会自动授予。

省略的能力字段表示不选择：子代理既不会继承父任务的选择，也不会回退为全部可用。过去省略 `skills` 表示可见全部技能，现在省略 `skills` 表示不选择任何技能。旧式空数组（`skills: []`）也读取为未选。保存非空选择时写为块式列表；清空某一类时直接从 YAML 文件删除该字段，而不是写入空数组。旧空数组只在下次保存对应分类时归一化为删除，不会批量迁移已有文件。`tools` 字段保持原有语义：省略或为空的 `tools` 仍然表示默认工具集。

每次运行的 system prompt 和有效选择在启动时冻结。修改配置后，下一次子代理运行或显式点击 **Retry** 时生效，没有热刷新。自动压缩沿用运行开始时冻结的 system prompt 与选择继续执行。

### Rules

已选规则会把完整正文直接注入子代理的 system prompt。规则不需要 loader 工具，Standard 与 Lite 提示词配置都可以使用。规则原有的 `paths` 条件只按子代理任务文本中出现的路径和子代理的工作目录求值，不借用父任务的全部消息或标签页。已选规则缺失、不可读或越出其根目录时，仅该子代理在请求 Provider 之前启动失败并给出可定位的原因，父任务和兄弟子代理不受影响；条件不匹配只是正常地不注入该规则。

### Skills 与 Workflows

Skills 与 Workflows 按需加载，需要 Standard 提示词配置和各自的 loader 工具：技能对应 `load_skill`，工作流对应 `load_workflow`。目录与加载消费同一份选择，猜测未选名称会被拒绝。已选技能或工作流消失或不可读时，选择会保留在界面中并标记为不可用，可以显式删除；Dline 不会改换同名资源。

### MCP

MCP 按 server 逐项选择：分别勾选工具与精确的资源 URI。在 Standard 提示词配置下，工具需要 `load_mcp` 与 `use_mcp_tool`；资源只需要 `access_mcp_resource`。选择按内部 server 名、原始工具名与精确 URI 匹配。不含 tools/resources 的 server 项表示不选择任何内容，保存时这些空子列表会被省略。

真实权限仍然生效：系统权限、工作区所有权、资源本身的可用与连接状态，以及原有的审批与 hook 机制都不会因选择而放宽。选择能力并不代替审批。

### 企业强制项

标记为 **Required by policy**（`alwaysEnabled`）的条目在界面中单独列出，普通勾选框无法关闭。强制的规则、技能或工作流即使未被写进子代理配置，每次运行也会被选中。但强制并不豁免上文的条件：强制规则仍按 `paths` 条件求值；强制技能与工作流仍需要 Standard 提示词配置和各自的 `load_skill` 或 `load_workflow` 工具，loader 门禁未满足的运行不会加载它们。

### 在界面中管理

在 **Manage Dline Rules & Workflows** 面板的 **Subagents** 标签页中，可以看到 **Global Subagents** 与 **Workspace Subagents** 两组，各有 **New subagent...** 按钮。每一行可以启用或停用、编辑或删除，并选择 **Profile**。展开一行后可以看到 **Tools**、**Rules**、**Skills**、**Workflows**、**MCP** 五个标签页。每个标签页显示生效与已选数量；缺少对应 loader 工具的选择会保留但不生效，重新启用工具后恢复，能力修改在下一次子代理运行时生效。

![能力面板的 Subagents 标签：Global Subagents 中的内置 default 与 Workspace Subagents 中的 code-researcher，两组各有 New subagent... 按钮](@docs-assets/ui/capabilities-subagents.png)

## 选择 Profile

| 情况 | 使用的 Profile |
|---|---|
| `profile` 指向一个已启用、且勾选了 **Subagents** 用途的 Profile | 该 Profile 的模型与思考配置，不套用主任务的任务级思考设置 |
| 省略 `profile`，或指向的 Profile 不可用、未启用或未勾选 Subagents 用途 | 回退到主任务的 **Act Profile**（即使主任务当前处于 Plan 模式） |
| 批量委派中某一项单独指定了 `profile` | 覆盖 YAML 中的设置；该 Profile 无效时，这一项会被拒绝，不会回退 |
| 子代理允许使用 `generate_image` | 必须显式指定一个有效的 Profile，否则失败 |

Profile 的创建与用途设置参见[模型配置](/zh-cn/getting-started/authorizing-with-dline/)。

## 自动压缩上下文

开启[自动压缩](/zh-cn/features/auto-compact/)后，子代理使用与主任务相同的触发、预留和 Maximum context 设置，按自己的模型上下文窗口计算。子代理会用自己的 Profile 汇总较早的上下文后继续工作。压缩沿用运行开始时冻结的 system prompt 与能力选择继续执行。压缩会产生额外的模型请求，并可能产生用量费用。

摘要和压缩状态只保存在运行内存中，重启扩展不会恢复已压缩的子代理对话。取消会停止正在进行的压缩；超时或点击 **Finish** 仍会要求子代理交回已有结论。压缩失败时，运行会报告失败。

关闭自动压缩时，子代理按 80% 的上下文用量阈值收尾。最终结果的输出预算独立设置，见下文。

## 最终结果的输出预算

`maxOutputTokens` 限制子代理交回主任务的最终结果大小，单位是 token：

- 不配置时，默认为启动时主任务剩余上下文的 5%；
- `0` 到 `1` 之间的小数表示比例，例如 `0.05`；
- 正整数表示固定 token 数，例如 `10240`；
- 生效预算最低为 512 token，即使主任务剩余上下文更少。

交回结果时，超出预算的部分会被截断。该预算只限制最终结果大小。

## 审批

- 启动子代理使用自动批准中的 **Read project files** 权限。
- 子代理内部的每个工具调用都要通过它的工具白名单和审批策略检查，**不会**再向你弹出逐个审批。需要人工审批的工具在子代理中会直接失败，而不是等待你确认。
- 执行命令时仍会应用命令权限和目录访问检查。

<Aside type="caution">
为具名子代理开放写文件或执行命令等工具前，请确认你接受这些操作在没有逐个确认的情况下发生（前提是审批策略允许）。
</Aside>

## 在聊天中查看

委派时聊天中会显示 “Dline wants to use a subagent:” 或 “Dline wants to use subagents:”。每个子代理有一张卡片，显示代理名称、前台或后台（**Foreground** / **Background**）、任务、工具和输出，以及运行状态。卡片提供 **Cancel**、**Cancel all**，以及在适用时的完成或重试按钮。

运行统计包括工具调用次数、耗时、token 用量和费用；子代理的用量会计入主任务的总用量。

## 与 `spawn_task` 的区别

需要独立的对话和进度记录时，可以让 Dline 使用 `spawn_task` 创建新任务；需要在当前任务中汇总调查结论时，使用子代理。工具的可用条件见[工具参考](/zh-cn/tools-reference/all-dline-tools/)。
