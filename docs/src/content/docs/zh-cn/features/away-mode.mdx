Away Mode 让当前任务在你暂时无法回复时，按已有范围和指令继续工作。该状态仅作用于当前任务。

<Aside>
本功能属于[实验性功能](/zh-cn/features/experimental/)。普通发行版参与灰度需要同时开启 Dline 的用量上报、错误上报，以及 VS Code、VSCodium 等宿主的全部遥测，并获得服务端开放资格。
</Aside>

## 开启与进入

灰度能力可用时，打开 **Settings → Features → Experimental → Away Mode**：

- **Enable Away Mode**：允许进入离开模式，默认关闭。
- **Automatic Away Mode**：新的普通问题十分钟无人回复时允许自动进入，默认也关闭。主选项关闭时，该选项禁用，但保留已保存的选择。

灰度不可用时，整组设置隐藏，但不会抹掉两项偏好。开启选项不会追溯为已经等待的问题启动计时。

主选项开启后，输入 `/away` 和任务正文并发送，或从命令菜单插入 Away：

```text
/away 继续完成实现，并运行聚焦测试。
```

任务正文、文件引用和附件会一并保留。请从命令菜单选择 Away；仅粘贴命令文本不会激活离开模式。再次进入会保持离开状态。

## 离开期间的变化

离开期间，Dline 会在已有范围和指令内继续工作，普通提问、计划确认和报告不再等待你的回答。

命令审批按工作区与命令工作目录区分：

- 分类为工作区内的命令可以使用当前任务的 Away 权限继续执行。
- 分类为工作区外的命令仍必须人工批准，优先于其他自动审批或 YOLO 设置。一分钟无人处理时，该审批以**未获批准**到期：不执行命令，也不视为用户主动拒绝。
- 其他工具保留原审批规则；工具禁用、权限规则、`.agentignore`、hooks 与显式指令仍然有效。

<Aside type="caution">
命令边界不会解析 shell 语法来推断命令可能影响的每一个文件或服务。Away Mode 不是沙箱；工作目录位于工作区内，不代表命令一定没有外部副作用。请按实际工作设置任务指令与命令权限。
</Aside>

重新打开任务后，倒计时按原来的截止时间继续。倒计时归零本身不会提交回答或批准命令。

## 退出 Away Mode，但不停止任务

使用任务底栏中的 **Stop Away Mode**。存在 Resume 或审批按钮时，它与这些按钮同栏；任务正在运行、没有当前问题时也可以使用。

该操作：

- 只退出 Away，不取消工具、不停止任务、不恢复任务，也不回答当前问题；
- 不提交、读取或清空输入框里尚未发送的草稿；
- 不改变全局偏好，原问题或审批继续等待；
- 退出成功后按钮消失；保存失败时可再次点击重试。

只读任务窗口显示状态，但禁用该操作；已完成任务不提供该操作。

发送普通内容也会退出 Away。编辑草稿、浏览历史、空 Resume，以及不带内容的单纯批准，不视为用户返回。关闭 **Automatic Away Mode** 只撤销未回答问题的自动进入资格，不退出已经处于 Away 的任务；关闭 **Enable Away Mode** 或灰度撤销，会退出已有模式，正在执行的工作继续。

后续模型请求恢复常规交互。退出不会额外发起 API 请求、取消在途请求或改写会话历史。
